## 1. 개요

### 1.1 목적
생성형 AI가 게임 마스터(GM)의 **서술(내레이션)** 을 맡고, 규칙 판정·아이템·전투·진행 상태는 **결정론적 게임 엔진**이 처리하는 웹 기반 TRPG 플랫폼을 만든다. 사용자는 직접 시나리오(TRPG 파일)를 제작·공유할 수 있으며, 여러 명이 한 세션에 접속해 함께 플레이할 수 있다.

### 1.2 핵심 목표
| # | 목표 | 설명 |
|---|------|------|
| G1 | 비용 최소화 | 텍스트 생성은 로컬 LLM 또는 무료 API를 사용한다. |
| G2 | 환각 통제 | 게임 상태(HP, 아이템, 플래그, 판정 결과 등)는 **엔진만** 바꿀 수 있다. AI는 상태를 읽고 묘사만 한다. |
| G3 | 사용자 창작 | 사용자가 시나리오 파일을 만들고, 검증하고, 테스트하고, 공유할 수 있다. |
| G4 | 멀티플레이 | 2~6인이 실시간으로 하나의 세션에 참여한다. |

### 1.3 범위 밖 (v1 기준)
- 이미지/음성 생성
- 모바일 네이티브 앱 (반응형 웹으로 대응)
- 유료 결제
- 외부 TRPG 룰(D&D 5e, CoC 등)의 공식 룰북 수록 (저작권 문제 — 사용자가 직접 룰을 정의하는 방식만 지원)

## 2. 핵심 설계 원칙

### 2.1 "엔진이 판정하고, AI는 이야기한다"

```
[플레이어 입력] → [의도 해석(AI, 구조화 출력)] → [엔진 검증·판정(코드)] → [상태 변경(코드)] → [서술 생성(AI)] → [출력 검증(코드)] → [플레이어에게 표시]
```

| 영역 | 담당 | 이유 |
|------|------|------|
| 주사위, 판정, 성공/실패 | 엔진 | 공정성·재현성 |
| HP/MP/스탯 변화 | 엔진 | 수치 환각 방지 |
| 아이템 획득/사용/소멸 | 엔진 | 없는 아이템 생성 방지 |
| 장면 이동, 이벤트 발동, 엔딩 | 엔진 (시나리오 그래프) | 스토리 이탈 방지 |
| NPC의 고정 정보(이름, 비밀, 핵심 대사) | 시나리오 파일 | 설정 붕괴 방지 |
| 자유 행동의 의도 분류 | AI (선택지 제한된 JSON 출력) | 자연어 이해 |
| 묘사, 분위기, NPC 즉흥 대사 | AI | 창의성 |

### 2.2 AI 권한 제한 규칙
1. AI는 게임 상태를 **직접 수정할 수 없다.** AI의 출력은 (a) 미리 정의된 행동 스키마 중 하나로의 분류 결과, 또는 (b) 순수 서술 텍스트뿐이다.
2. AI에게 전달되는 컨텍스트는 엔진이 확정한 **"사실 목록(Fact Sheet)"** 이며, 서술은 이 사실 안에서만 이루어져야 한다.
3. AI 서술 결과는 출력 검증기(§5.4.4)를 통과해야 표시된다.

|------|------|-----------|

| 관리자 | 운영자 | 신고 처리, 시나리오 비공개 처리, 사용자 제재 |

## 4. 시스템 구성

```
┌──────────────┐   WebSocket / HTTP   ┌───────────────────────────────────────┐
│  Web Client  │ ◄──────────────────► │              API Server               │
│ (React/Next) │                      │  ┌─────────┐ ┌──────────┐ ┌────────┐  │
└──────────────┘                      │  │ Session │ │  Game    │ │Scenario│  │
                                      │  │ Manager │ │  Engine  │ │Service │  │
                                      │  └────┬────┘ └────┬─────┘ └────────┘  │
                                      │       │      ┌────▼─────┐             │
                                      │       │      │ AI Orches│             │
                                      │       │      │ -trator  │             │
                                      └───────┼──────┴────┬─────┴─────────────┘
                                              │           │
                                       ┌──────▼──┐  ┌─────▼───────────────────┐
                                       │ DB/Redis│  │ LLM Provider Adapter     │
                                       └─────────┘  │ (Ollama / llama.cpp /    │
                                                    │  vLLM / 무료 API)        │
                                                    └──────────────────────────┘
```

| 모듈 | 책임 |
|------|------|
| Session Manager | 방 생성/참여, 접속 관리, 턴/라운드 진행, 브로드캐스트 |
| Game Engine | 룰 실행, 상태 관리, 이벤트/트리거 평가 (순수 함수 + 시드 기반 난수) |
| Scenario Service | 시나리오 저장, 스키마 검증, 버전 관리, 공유 |
| AI Orchestrator | 프롬프트 조립, LLM 호출 큐, 구조화 출력 파싱, 출력 검증, 재시도 |
| LLM Provider Adapter | OpenAI 호환 인터페이스로 여러 백엔드를 추상화 |

#### 5.4.2 행동 스키마 (의도 해석 결과)
AI는 아래 형식으로만 응답하도록 강제한다 (JSON 스키마 / grammar 제약 출력 사용).

```json
{
  "action": "move | examine | talk | use_item | attack | skill_check | give | free_roleplay",
  "target": "시나리오에 존재하는 ID 또는 null",
  "item": "보유 아이템 ID 또는 null",
  "stat": "판정 시 사용할 스탯 ID 또는 null",
  "utterance": "플레이어가 말한 대사(있을 경우)"
}
```

- `target`, `item`, `stat`은 엔진이 **현재 유효한 후보 목록**을 함께 제공하고, 그 외 값은 거부한다.
- 파싱 실패 또는 무효 값 → 1회 재시도 → 실패 시 `free_roleplay`로 처리(상태 변화 없음, 서술만).
- 애매한 입력은 플레이어에게 선택지 버튼으로 되묻는다. (예: "어느 문을 여시겠습니까? [북쪽 문] [지하실 문]")

#### 5.4.3 Fact Sheet (서술 생성 입력)
```yaml
scene: 버려진 예배당
present_npcs: [늙은 사제 오스카]
action_result:
  actor: 리아
  action: use_item
  item: 녹슨 열쇠
  check: { stat: 민첩, roll: 14, dc: 12, result: 성공 }
  state_changes:
    - 지하실 문이 열림
    - "녹슨 열쇠" 소멸
must_mention: [지하실로 내려가는 계단]
must_not_reveal: [오스카가 범인이라는 사실]
tone: 음울한 고딕 호러
max_length: 3문장
```

#### 5.4.4 출력 검증기 (환각 방지)
| 검사 | 방법 | 실패 시 |
|------|------|--------|
| 미존재 아이템 언급 | 서술 내 아이템 사전 매칭: 획득 문맥으로 미보유 아이템이 등장하는지 검사 | 재생성 |
| 판정 결과 모순 | 결과가 실패인데 "성공적으로" 등 반대 표현 사용 | 재생성 |
| 비밀 누설 | `must_not_reveal` 키워드/유사도 검사 | 재생성 |
| 수치 언급 | 서술에서 HP·데미지 숫자 출력 금지 (수치는 UI가 표시) | 숫자 제거 또는 재생성 |
| 길이 초과 | 최대 길이 | 잘라내기 |
| 재생성 한도 초과 | 최대 2회 | 폴백 텍스트(F-AI-10) |

> 원칙: 서술에 오류가 있더라도 **게임 상태는 이미 엔진이 확정**했으므로 상태에는 영향이 없다. 검증기는 "플레이어가 오해할 만한 서술"을 줄이는 목적이다.

## 6. 시나리오 파일 포맷 (v1)

- **파일**: `.trpg` 패키지(zip) 안의 `scenario.yaml` (UTF-8 YAML)
- **정식 스키마**: [backend/src/modules/scenario/scenario.schema.ts](../backend/src/modules/scenario/scenario.schema.ts) (Zod). 이 절과 스키마 코드는 항상 함께 수정한다.
- **검증**: `POST /api/v1/scenarios/validate` (BE-SCN-10) 또는 `cd backend && npm run validate:scenario -- <파일>`
- **전체 예제**: [scenarios/neo-dimigo/scenario.yaml](../scenarios/neo-dimigo/scenario.yaml) — 이 절의 모든 기능을 사용

### 6.1 공통 규칙

| 항목 | 규칙 |
|------|------|
| ID | 아이템·장면·NPC·적·상태이상·프리셋·오브젝트·이벤트·엔딩·플래그·변수 ID는 영문 소문자로 시작하는 snake_case (`laptop_battery`). 시나리오 ID(`meta.id`)만 kebab-case |
| 스탯 이름 | `ruleset.stats`에 정의한 문자열 그대로 사용 (한글 가능) |
| 주사위/수치 | 정수 또는 `NdM±K` 표기 (`3`, `-1`, `1d20`, `2d6+1`, `-1d4`) |
| 조건식 | §6.6 DSL 문자열 |
| 알 수 없는 키 | 오류 (오타 방지) |
| 플래그 | 선언 없이 `set_flag`로 생성, 기본값 false |
| 변수 | `variables`에 초기값 선언 필수 |

### 6.2 최소 예시

```yaml
format_version: 1
meta:
  id: chapel-mystery
  title: 버려진 예배당의 비밀
  author: user123
  players: { min: 1, max: 4 }
  estimated_minutes: 60
  rating: 전체
  tags: [호러, 추리]
  language: ko
  start_scene: chapel_hall

ruleset:
  stats: [힘, 민첩, 지능, 매력]
  resources:
    hp: { max: "10 + 힘", min: 0 }
  check: { dice: "1d20", formula: "roll + stat" }
  critical: { success: 20, failure: 1 }

ai_guide:
  tone: 음울한 고딕 호러
  narration_length: short       # short | medium | long
  world_lore: |
    1890년대 영국의 작은 마을. 마을 사람들은 예배당 이야기를 꺼린다.

items:
  rusty_key:
    name: 녹슨 열쇠
    description: 손잡이에 십자가 문양이 새겨진 열쇠.
    consumable: true
    effects: []
  holy_water:
    name: 성수
    consumable: true
    effects:
      - { op: add_resource, resource: hp, value: "1d6" }

npcs:
  oscar:
    name: 늙은 사제 오스카
    personality: 친절해 보이지만 질문을 받으면 말을 돌린다.
    speech_style: 느리고 고풍스러운 존댓말
    knows: [예배당의 역사, 지하실의 존재]
    secrets: [실종 사건의 범인이다]       # AI 서술 시 must_not_reveal 로 주입
    fixed_lines:
      greeting: "길 잃은 양이 또 찾아왔군요."

scenes:
  chapel_hall:
    name: 예배당 본당
    description: 깨진 스테인드글라스 사이로 달빛이 들어온다.
    npcs: [oscar]
    objects:
      altar:
        name: 제단
        on_examine:
          check: { stat: 지능, dc: 12 }
          success:
            - { op: give_item, item: rusty_key }
            - { op: narrate_hint, text: 제단 아래 숨겨진 열쇠를 발견했다. }
          failure:
            - { op: narrate_hint, text: 특별한 것은 보이지 않는다. }
      font:
        name: 성수반
        on_examine:
          condition: "not flag('holy_water_taken')"
          locked_text: 성수반이 말라 있다.
          actions:
            - { op: give_item, item: holy_water }
            - { op: set_flag, flag: holy_water_taken, value: true }
    exits:
      - to: basement
        label: 지하실 문
        condition: "flag('basement_unlocked')"
        locked_text: 문이 단단히 잠겨 있다.

  basement:
    name: 지하실
    description: 축축한 공기와 쇠 냄새.
    on_enter:
      - { op: start_combat, enemies: [ghoul] }
    objects:
      journal:
        name: 고해 일지
        on_examine:
          actions:
            - { op: set_flag, flag: oscar_confessed, value: true }
            - { op: reveal_secret, npc: oscar, secret: 실종 사건의 범인이다 }
    exits:
      - { to: chapel_hall, label: 계단 }

events:
  - id: unlock_basement
    trigger: { type: use_item, item: rusty_key, target: chapel_hall.exits.basement }
    actions:
      - { op: set_flag, flag: basement_unlocked, value: true }

enemies:
  ghoul:
    name: 구울
    hp: 12
    attack: { dice: "1d6+1" }
    behavior:                    # 적 AI도 테이블 기반 (LLM 아님)
      - { when: "hp < 4", do: flee }
      - { default: attack_random }

endings:
  - id: truth_revealed
    title: 진실
    condition: "flag('oscar_confessed')"
    text: 마침내 진실이 밝혀졌다...
  - id: all_dead
    title: 또 다른 희생자
    condition: "all_players_down()"
    text: 예배당은 또 다른 희생자를 삼켰다.
```

| `meta` | ✓ | 시나리오 정보 |
| `ruleset` | ✓ | 스탯, 자원, 판정, 캐릭터 생성 규칙 |

### 6.4 섹션별 필드

**meta**

| 필드 | 필수 | 형식 |
|------|:---:|------|
| `id` | ✓ | kebab-case |
| `title`, `author`, `language` | ✓ | 문자열 |
| `summary` | | 문자열 |
| `players` | ✓ | `{ min, max }` (min ≤ max) |
| `estimated_minutes` | ✓ | 양의 정수 |
| `rating` | ✓ | `전체` \| `12세` \| `15세` \| `18세` |
| `tags` | ✓ | 문자열 배열 |
| `start_scene` | ✓ | 장면 ID |

**ruleset**

| 필드 | 필수 | 형식 |
|------|:---:|------|
| `stats` | ✓ | 스탯 이름 배열 |
| `resources` | ✓ | `{ <자원 ID>: { max, min } }` — 값은 숫자 또는 식(`"10 + 체력"`) |
| `check` | ✓ | `{ dice, formula }` |
| `critical` | | `{ success, failure }` (주사위 원값) |
| `character_creation` | | `{ method: point_buy, total_points, min_per_stat, max_per_stat, allow_custom }` |

**presets** — `{ <ID>: { name, description, stats: { <스탯>: 값 } } }`. 스탯 키는 `ruleset.stats`와 일치, 합계는 `total_points`, 각 값은 min~max 범위.

**variables** — `{ <변수 ID>: 정수 초기값 }`

**statuses** — `{ <ID>: { ... } }`

| 필드 | 필수 | 설명 |
|------|:---:|------|
| `name` | ✓ | 표시 이름 |
| `description` | | 설명 |
| `duration` | ✓ | 지속 턴 수 또는 `until_removed` |
| `restrict_actions` | | true면 자유 행동 불가 |
| `on_turn_start` | | 턴 시작 시 실행할 op 목록 |
| `resist` | | `{ check, on_success }` — 매 턴 시작 시 저항 판정 |

**ai_guide**

| 필드 | 필수 | 설명 |
|------|:---:|------|
| `tone` | ✓ | 문체/분위기 |
| `narration_length` | ✓ | `short` \| `medium` \| `long` |
| `world_lore` | ✓ | 세계관 설명 (프롬프트 주입) |
| `style_rules` | | 서술 규칙 목록 |
| `glossary` | | `{ 용어: 설명 }` — 고유명사 표기 고정 |

**items** — `{ <ID>: { name, description?, consumable, effects: op[] } }`. `effects`는 사용 시 실행되며, 대상을 지정하면 대상 캐릭터에게 적용된다.

**npcs** — `{ <ID>: { name, personality, speech_style?, knows: [], secrets: [], fixed_lines?: { 키: 대사 } } }`. `secrets`는 서술 시 `must_not_reveal`로 주입되고, `reveal_secret` op로만 공개된다.

**scenes** — `{ <ID>: { name, description, npcs?, on_enter?: op[], objects?, exits } }`

- `objects`: `{ <ID>: { name, on_examine?, on_interact? } }` — `on_examine`은 조사, `on_interact`는 직접 행동(열기, 뽑기, 공중제비 등)
- `exits`: `[{ to, label, condition?, locked_text? }]` (출구가 없으면 `[]`)

**상호작용 블록** (`on_examine`, `on_interact`, `events`의 본문 공통) — 두 형태 중 하나:

```yaml
# 판정 없음
condition: "..."        # 선택. 거짓이면 locked_text 출력
locked_text: "..."      # 선택
actions: [op, ...]

# 판정 있음
condition: "..."
check:
  stat: 체력
  dc: 15
  modifiers:            # 선택. 조건이 참이면 판정값에 bonus 가산
    - { when: "flag('irrigation_off')", bonus: 6 }
success: [op, ...]
failure: [op, ...]
```

**events** — `[{ id, trigger, ...상호작용 블록 }]`

| trigger.type | 추가 필드 | 발동 시점 |
|------|------|------|
| `use_item` | `item`, `target?` (`<장면>.objects.<ID>` 또는 `<장면>.exits.<장면 ID>`) | 아이템을 대상에 사용할 때 |
| `enter_scene` | `scene` | 장면에 들어갈 때마다 (1회만 원하면 플래그 조건 사용) |
| `condition` | — | `condition`이 참이 되는 순간 1회 (`condition` 필수) |

**enemies** — `{ <ID>: { ... } }`

| 필드 | 필수 | 설명 |
|------|:---:|------|
| `name` | ✓ | |
| `hp` | ✓ | 정수 또는 식 (`"30 + 8 * party_size()"`) |
| `attack` | ✓ | `{ dice, targets?: single \| all }` |
| `skills` | | `{ <ID>: { name, attack?, effects?: op[] } }` |
| `behavior` | ✓ | `[{ when: 식, do: 행동 }, ..., { default: 행동 }]` — 위에서부터 첫 번째로 참인 항목 실행. 행동: `attack_random` \| `attack_lowest_hp` \| `flee` \| `skill:<ID>`. 식에서 `hp`는 적 자신의 현재 HP |
| `on_defeat` | | 처치 시 실행할 op 목록 |

**endings** — `[{ id, title, condition, text }]`. 매 처리 후 위에서부터 검사해 처음 참인 엔딩으로 종료.

### 6.5 연산(op) 목록 (v1)

| op | 파라미터 | 설명 |
|----|------|------|
| `give_item` | `item`, `quantity?` | 아이템 지급 |
| `remove_item` | `item`, `quantity?` | 아이템 제거 |
| `add_resource` | `resource`, `value` | 자원 증감 (`value`: 정수/주사위, 음수 가능) |
| `set_resource` | `resource`, `value` | 자원 값 설정 |
| `set_flag` | `flag`, `value` | 플래그 설정 |
| `add_var` | `var`, `value` | 변수 증감 |
| `move_party` | `scene` | 파티 이동 |
| `start_combat` | `enemies` | 전투 시작 (적 ID 배열, 중복 가능) |
| `end_combat` | — | 전투 종료 |
| `apply_status` | `status`, `save?: { stat, dc }` | 상태이상 부여. `save`가 있으면 대상이 저항 판정 |
| `remove_status` | `status` | 상태이상 해제 |
| `narrate_hint` | `text` | AI 서술에 반영할 사실 (AI가 문장을 다듬음) |
| `fixed_text` | `text` | 원문 그대로 출력 (AI가 수정하지 않음) |
| `reveal_secret` | `npc`, `secret` | NPC 비밀 공개 (`secret`은 해당 NPC `secrets`의 문장과 일치) |
| `trigger_ending` | `ending` | 즉시 엔딩 |

### 6.6 조건식 DSL (v1)

| 함수 | 설명 |
|------|------|
| `flag(id)` | 플래그 값 |
| `var(id)` | 변수 값 |
| `has_item(id)` | 파티 중 누군가 보유 |
| `stat(이름)` | 행동 캐릭터의 스탯 |
| `resource(id)` | 행동 캐릭터의 자원 |
| `in_scene(id)` | 파티가 해당 장면에 있는지 |
| `turn_count()` | 세션 전체 경과 턴 |
| `all_players_down()` | 전원 행동 불능 |
| `party_size()` | 파티 인원 |

- 연산자: `and`, `or`, `not`, `==`, `!=`, `<`, `<=`, `>`, `>=`, `+`, `-`, `*`, 괄호
- 식별자: 자원 식에서는 스탯 이름(`10 + 체력`), 적 `behavior`에서는 `hp`
- 임의 코드 실행 불가 — 화이트리스트 파서로만 평가 (F-ENG-09)

### 6.7 검증 규칙

검증기는 **오류**가 하나라도 있으면 저장을 거부하고, **경고**는 저장을 허용한다. 모든 항목에 경로(`scenes.hall.exits.0.to`)와 줄 번호를 붙여 반환한다.

| 단계 | 오류 | 경고 |
|------|------|------|
| YAML | 문법 오류, 중복 키 | |
| 스키마 | 필수 누락, 형식 불일치, 알 수 없는 키, 허용되지 않은 op/trigger/행동, check·actions 조합 위반 | |
| 참조 | 없는 장면·아이템·NPC·적·상태이상·스킬·자원·엔딩·스탯 참조, 선언되지 않은 변수, `set_flag` 없이 조건에만 쓰인 플래그, `secrets`에 없는 `reveal_secret`, 중복 이벤트/엔딩 ID, 프리셋 스탯 불일치 | 설정만 되고 쓰이지 않는 플래그, 얻을 수 없는 아이템, 전투에 등장하지 않는 적, 배치되지 않은 NPC, `default` 없는 적 행동 |
| 그래프 | 시작 장면에서 도달할 수 없는 장면 (출구와 `move_party` 기준, 조건 무시) | |

> v2 예정: `ruleset_ref`로 룰셋 분리(F-SCN-13), 장면 그래프 기반 엔딩 도달 가능성 검사

## 7. 턴 처리 흐름 (라운드 모드)

```
1. 라운드 시작 → 서버가 "행동 입력" 상태 브로드캐스트 (제한 시간 표시)
2. 각 플레이어 입력 (자유 텍스트 or 추천 행동 버튼)
3. 전원 입력 or 시간 초과 → 입력 잠금
4. 플레이어별 의도 해석 (AI, 구조화 출력)   ※ 버튼 입력은 AI 생략
5. 엔진: 유효성 검사 → 판정 → 상태 변경 → 트리거 평가 → 엔딩 검사
6. 상태 변경 결과를 즉시 브로드캐스트 (캐릭터 시트·주사위 UI 갱신)
7. Fact Sheet 조립 → AI 통합 서술 생성 (스트리밍)
8. 출력 검증 → 실패 시 재생성/폴백
9. 서술 확정 → 로그 저장 → 다음 라운드
```

> 5~6단계가 7단계보다 먼저 끝나므로, AI가 느리거나 실패해도 **게임 결과는 이미 플레이어에게 보인다.**

## 8. 비기능 요구사항

| 분류 | 요구사항 |
|------|---------|
| 성능 | 엔진 처리 200ms 이내. AI 첫 토큰 5초 이내(로컬 7~14B 모델 기준 목표), 대기 중 진행 표시 |
| 동시성 | v1 목표: 동시 세션 10개 (로컬 GPU 1대 기준). LLM 큐로 처리량 제어 |
| 신뢰성 | 세션 상태는 매 라운드 영속 저장. 서버 재시작 후 복구 가능 |
| 보안 | 시나리오 DSL은 화이트리스트 파서로만 해석 (eval 금지). 업로드 파일 크기 제한. 프롬프트 인젝션 대비: 플레이어 입력은 항상 데이터로 구분해 주입, AI는 상태 변경 권한 없음 |
| 공정성 | 서버 측 난수 생성만 허용. 클라이언트는 결과 표시만 |
| 이식성 | LLM 백엔드는 설정 파일로 교체 (코드 수정 불필요) |
| 다국어 | v1은 한국어. 시나리오 `language` 필드로 확장 대비 |
| 접근성 | 키보드만으로 플레이 가능, 스크린리더 대응 텍스트 |

## 11. 미결 사항 (결정 필요)

1. **LLM 호스팅 위치**: 서버에서 로컬 LLM을 운영할지, 사용자 PC의 로컬 LLM(Ollama)에 브라우저가 직접 연결하는 "BYO-LLM" 모드도 지원할지? (후자는 서버 비용 0, 대신 멀티플레이 시 호스트 PC가 AI를 담당)
2. **룰셋 범위**: 범용 d20 계열 하나로 시작할지, d100/2d6 등 여러 판정 방식을 v1부터 지원할지?
3. **시나리오 자유도**: 장면 그래프 밖의 행동(예: "마을을 불태운다")을 어디까지 허용할지? — 제안: 상태 변화 없는 `free_roleplay`로만 처리
4. **콘텐츠 정책**: 사용자 제작 시나리오의 성인 등급 허용 여부와 검수 방식
5. **무료 API 사용 시 데이터**: 플레이어 입력이 외부 API로 전송된다는 점의 고지 방식
6. **시나리오 저작권/라이선스**: 공개 시나리오의 기본 라이선스(포크 허용 여부) 정책
